# 本地 RAG 可行性验证

本目录只提供可插拔的全文检索准备层，不改变实时 arXiv/OpenAlex 主流程，也不预先绑定向量库或 GraphRAG 产品。

## 放置论文

将用户选择的 5～10 篇测试论文放入 `data/papers/`。PDF 文件被 Git 忽略，不会随代码提交。

## 三层数据原则

```text
原始层：PDF + SHA-256 + 来源版本
→ 解析层：逐页文本 + Chunk + Parser/Chunker 版本
→ 索引层：BM25 / Dense / Graph 等可删除、可重建索引
```

PDF 哈希、Parser 版本或 Chunker 版本变化时，只重建受影响论文。Embedding 或检索技术变化时只替换索引层。

## 人工标注

复制 `eval_harness/datasets/rag_annotation_template.json`，为每个问题填写参考答案、支持证据、PDF 页码和来源路径。第一轮建议 5～10 篇论文、15～20 个问题。

## 当前边界

- 已有逐页 `PyPDFPageParser`，不包含 OCR 和表格识别。
- 已有固定窗口 Chunker，作为最简单基线。
- 已有不依赖外部库的 BM25 内存基线，采用英文词与中文单字/双字混合分词；它只用于建立可审计下限，不是最终选型。
- 首次 16 题精确 Chunk 评测得到 Recall@5 18.75%、MRR@5 10.94%、nDCG@5 12.89%，主要暴露中文问题与英文全文的词汇鸿沟。
- 确定性中英术语扩展在当前开发集把精确 Chunk Recall@5 提升到 75.00%，Page Recall@5 提升到 81.25%，9 题提升、0 回归；但术语表参考了这 16 题，只能证明机制潜力，不能作为生产晋升证据。
- 冻结术语表后新增 10 题独立保留集，覆盖 8 篇论文且证据页与开发集零重叠。保留集 Chunk Recall@5 维持 60.00%，nDCG@5 从 46.93% 降至 44.92%，0 题提升、1 题回归，因此规则扩展不晋升。
- 尚未建立持久化知识库或向量索引。后续先建立未参与术语设计的保留集，再实现多语言 Dense，通过同一评测决定是否增加 Hybrid 或图检索。

## 多语言 Dense 基线（2026-08-13）

- 新增可插拔 `DenseRetriever`：Embedding 后显式 L2 归一化，以余弦相似度排序；相同分数按原始 Chunk 顺序确定性打破平局。
- 首个候选为 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，通过 FastEmbed 0.7.4 和 ONNX Runtime CPU 运行，不调用 LLM。
- 相同 1098 个 Chunk 上，开发集 Chunk Recall@5 从 BM25 的 18.75% 提升至 25.00%；独立保留集从 60.00% 提升至 80.00%，nDCG@5 从 46.93% 提升至 59.05%。
- 保留集逐题为 4 个提升、3 个回归、3 个不变；首次索引构建约 119 秒，Dense 平均查询约 334.54ms，BM25 约 14.39ms。
- 因仍有逐题回归且尚未持久化向量索引，该方案只作为实验候选，生产默认继续关闭。下一步先做索引缓存与重复性测试，再使用相同语料和标注对照第二个多语言 Dense，最后才评测 Hybrid。
- 已新增基于 SHA-256 指纹的 `.npy` 向量缓存；指纹覆盖完整 Chunk 内容与身份、Parser/Chunker 版本和模型名。真实冷启动编码约 61.62 秒，热启动缓存读取约 10.58ms、检索器构造约 2.99ms，质量指标完全一致。缓存只解决重复编码，查询仍需实时生成 Embedding；下一步进入重复运行稳定性评测。
- 已完成 3 次独立 Python 进程热启动稳定性评测：全部命中同一缓存指纹，开发集与保留集质量指标、每题 Top-5 Chunk 顺序和分数完全一致。模型加载均值约 3.45 秒，缓存读取均值 9.09ms，检索器构造均值 3.14ms；开发集/保留集平均查询分别约 78.22/78.61ms，变异系数 45.53%/28.96%。稳定性门槛通过，但开发集延迟波动接近 50% 上限，生产开关继续关闭；下一步进入第二个多语言 Dense 模型单变量对照。
- 第二模型选择 `paraphrase-multilingual-mpnet-base-v2`，模型文件与索引统一保存在 `D:/langgraphproject/data/cache/`，不使用用户目录缓存。相同保留集上 MPNet 与 MiniLM 的 Chunk Recall@5 均为 80%，但 MRR@5 从 52.33% 提升至 70.00%、nDCG@5 从 59.05% 提升至 72.62%；逐题 4 提升、1 回归、5 不变。代价是 768 维向量、冷建库约 317.5 秒、热查询约 96.81ms。MPNet 晋升为首选 Dense 候选，生产默认仍关闭；下一步先做 MPNet 独立进程稳定性，再决定是否用 Hybrid 修复 RAG decoding 回归。
